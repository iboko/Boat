# Boat — автономная навигация беспилотного надводного судна

**v0.7 — исследовательский каркас C++20. Только моделирование, не для реального плавания.**

[![C++ build and tests](https://github.com/iboko/Boat/actions/workflows/ci.yml/badge.svg)](https://github.com/iboko/Boat/actions/workflows/ci.yml)

Цель проекта — движение по маршрутным точкам с обязательной ИНС и установленным ГНСС, который не является единственным источником навигации. При потере ГНСС предполагается коррекция по независимым измерениям береговых ориентиров и скорости относительно дна, контроль погрешности и безопасное прекращение выполнения маршрута, когда достоверность координат не обеспечивается.

## Новое в v0.7 — моделируемые датчики → C++ ESKF → ArduPilot AUTO

- Добавлен C++ генератор трех отдельных **синтетических** каналов: инерциальный датчик с остаточными смещениями и шумом, геопривязанная береговая координатная коррекция и скорость относительно дна; без использования спутниковой навигации.
- Датчики объединяются существующим 15-состоянийным ESKF. Новый `boat_sitl_sensor` отправляет в ArduPilot `ODOMETRY` на основании **оценки фильтра**, а не прямых координат `SIM_STATE`.
- Замкнутый контур AUTO Rover SITL подтвердил три маршрутные точки при отключенном ГНСС; P95 ошибки EKF ArduPilot относительно физической модели — 0,433 м, максимальная ошибка C++ ESKF — 0,272 м.
- В одном успешном испытании зарегистрированы 224 отправленных ODOMETRY, 24 геопривязки по условной береговой РЛС, 58 измерений скорости условным донным лагом; пропущены 5 и 6 измерений соответственно. Учебный сценарий относится к физической модели Rover, а не к морской гидродинамике.
- Проверка пропусков датчиков, старения абсолютной коррекции, ошибок C++ ESKF и фактического достижения точек автоматизирована в CI. Полный протокол: [docs/sensor_sitl.md](docs/sensor_sitl.md).

**Ограничение:** показания виртуальных датчиков получают из `SIM_STATE` с добавленными ошибками. Модели реальных РЛС, IMU, DVL, течения, ветра и волн отсутствуют. Результат нельзя интерпретировать как достигнутую точность в море.

## Новое в v0.6 — динамическая миссия AUTO в Rover SITL

- Отдельное C++ приложение `boat_sitl_dynamic` передает в ArduPilot `ODOMETRY` по TCP на основании **только синтетических испытательных** данных SIM_STATE физической модели.
- Подтверждено фактическое движение виртуальной модели Rover по всем трем маршрутным точкам в AUTO при `GPS1_TYPE=0`, `GPS2_TYPE=0`, `EK3_SRC1_POSXY=6`.
- Проверены обратное подтверждение EKF origin, heartbeat режимов AUTO/ARMED, сообщения `MISSION_ITEM_REACHED` для точек 1, 2 и 3, физические координаты SIM_STATE и согласование с EKF.
- Успешное испытание: 220 динамических обновлений, минимальное расстояние до финальной точки 0,08 м, P95 расхождения EKF/физической модели 0,349 м. **Это результат с искусственно точным источником**, не оценка точности реальных ИНС, РЛС или лага.
- Код миссии защищен проверкой `SIM_STATE` **до** любых команд записи/ARM, а сам C++-передатчик требует явный `--sitl-dynamic-fixture`.
- Все результаты и ограничения описаны в [docs/dynamic_sitl.md](docs/dynamic_sitl.md).

## Новое в v0.5 — передача маршрута через MAVLink

- Реальный Rover SITL при отключенном ГНСС принимает четыре записи маршрута, сохраняет их и возвращает при запросе; координаты проверяются автоматически.
- Загрузка миссии проверяется в отдельном тестовом канале `SERIAL2` без вооружения и движения.
- Положительные результаты не означают, что режим AUTO успешно прошел маршрут; это следующий этап.

## Новое в v0.4 — SITL EKF origin и навигационная телеметрия

- Проверка, что ArduPilot действительно подтвердил геодезическое начало координат `GPS_GLOBAL_ORIGIN` без ГНСС.
- Сбор телеметрии `EKF_STATUS_REPORT` и `LOCAL_POSITION_NED` при потоке `ODOMETRY`.
- Строгая приемка по сообщению EKF3 об использовании внешней навигации и флагам горизонтального позиционирования.
- JSON-отчеты в CI. **Прохождение маршрута AUTO еще не реализовано и не подтверждено**.

## Новое в v0.3 (SITL, протокольная интеграция)

- C++ TCP MAVLink-компаньон для ArduPilot SITL (loopback), с проверкой HEARTBEAT и контролем допустимости ODOMETRY.
- Разделение измерений настоящей 3D ИНС и тестового синтетического источника: `--sitl-fixture` обязательно передает только синтетические данные и никогда не вооружает лодку.
- Тесты TCP и приемника MAVLink с фиктивным сервером, CI-проверка с официальными заголовками; экспериментальная проверка с реальным исполняемым Rover SITL.
- Требования и сценарии: [docs/sitl_integration.md](docs/sitl_integration.md).

**Важно:** передача MAVLink пакетов не подтверждает работу EKF3 по внешней навигации и выполнение маршрутных точек без ГНСС.

## Реализовано в v0.1

- Библиотека boat_core (C++20, CMake, CTest);
- упрощенная 2D-модель инерциального счисления по угловой скорости и уже компенсированным ускорениям; НЕ полноценная ИНС;
- коррекция положения по ГНСС либо независимым береговым координатам, отбраковка очевидных выбросов;
- коррекция скорости только относительно грунта, без подмены ее скоростью лага относительно воды;
- маршрутные точки, проверка достоверности навигации и приостановка выдачи наведения;
- синтетическая симуляция отключения ГНСС на участке 20–160 с, где используются имитированные независимые береговые измерения;
- опциональный кодировщик MAVLink ODOMETRY только для отдельно подтвержденного 6D-состояния (без UART/UDP);
- CI для сборки и тестов.

## Сборка и испытание

Требуется CMake 3.20+ и компилятор C++20.

    cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
    cmake --build build --parallel
    ctest --test-dir build --output-on-failure
    ./build/boat_sim > trajectory.csv
    ./build/boat_ins_demo > ins_3d_trajectory.csv

Выходной CSV содержит эталонные и оцененные координаты, расчетную ошибку, формальную неопределенность, режим и индекс точки.

## ArduPilot

План: отдельный вычислитель Boat передает достоверные данные в ArduPilot Rover/Boat через MAVLink 2, ArduPilot управляет двигателем, рулем, миссией AUTO и аварийным перехватом. При необходимости исследуем отдельный режим GUIDED, но режимы не должны конкурировать. Адаптер ODOMETRY включается только при наличии официальных заголовков MAVLink 2:

    cmake -S . -B build -DBOAT_WITH_MAVLINK=ON -DBOAT_MAVLINK_INCLUDE_DIR=/path/to/mavlink-headers

Нельзя выдавать результаты текущей 2D-модели за полноценную внешнюю 6D-навигацию. Ветка v0.1 не отправляет команды движения и не управляет исполнительными механизмами.

## Ограничения и предстоящие работы

Не реализованы: 3D-инерциальная механизация, ESKF, реальные драйверы IMU/INS и лага, радиолокационное сопоставление с картой, физический транспорт MAVLink, интеграционные тесты SITL, обнаружение препятствий, МППСС-72, натурные испытания.

Документация: docs/architecture.md, docs/ins_eskf.md, docs/dynamic_sitl.md, docs/sitl_integration.md, docs/ardupilot.md, docs/roadmap.md.

**Предупреждение:** не подключать эту версию к двигателю и рулевому механизму реальной лодки. Лицензия проекта пока не выбрана.
