# Boat v0.6: динамический Rover SITL с отключенным ГНСС

## Цель

Проверить **замкнутый контур** ArduPilot EKF3 → режим AUTO → виртуальный двигатель/руль → физическая модель Rover → внешняя навигационная коррекция C++ → EKF3, используя географический источник ExternalNav вместо ГНСС.

## Источники данных и ограничения

Внешняя траектория строится по сообщению **SIM_STATE** самого физического симулятора ArduPilot (поля `lat_int`, `lon_int`, `vn`, `ve`, `yaw` и т. д.), а **не** по `LOCAL_POSITION_NED` EKF3. Данные SIM_STATE подаются на стандартный ввод `boat_sitl_dynamic`; программа на C++ преобразует их в LOCAL_FRD/BODY_FRD MAVLink ODOMETRY с небольшой детерминированной искусственной координатной погрешностью. Независимая тестовая программа на Python проверяет истинное положение и регистрирует параллельные оценки EKF.

ЭТО ИСПЫТАТЕЛЬНАЯ ПОДМЕНА ДАТЧИКОВ. **Реальная ИНС/РЛС/донный лаг не измеряют эти значения**, поэтому успех AUTO **не доказывает** точность или устойчивость навигации на реальной лодке без ГНСС. Физическая модель `--model rover` — наземная модель с `FRAME_CLASS=2`, а не корректная морская гидродинамика. Отдельные испытания ESKF остаются в `boat_ins_tests` и `boat_ins_demo`; в динамическом режиме v0.6 их выход еще НЕ является основным источником ODOMETRY.

## Запуск и защита

Запускать только на выделенной машине в SITL:

```bash
cmake -S . -B build-mavlink -DCMAKE_BUILD_TYPE=Release \
 -DBOAT_WITH_MAVLINK=ON -DBOAT_MAVLINK_INCLUDE_DIR=/path/to/mavlink/c_library_v2
cmake --build build-mavlink --parallel
ARDUROVER_BINARY=/path/to/ardurover bash tools/sitl/run_sitl_dynamic.sh
```

Требуется Python `pymavlink` только для испытательной оркестрации. Автопилот запускается на localhost; связь с реальным контроллером отсутствует. Перед выполнением маршрута отдельный клиент подтверждает физическое отсутствие ГНСС в параметрах, заданный EKF origin и передачу внешней одометрии. Команды AUTO и ARM генерируются только после явного `--sitl-only`. При выходе отправляются HOLD и обычная команда DISARM (без принудительного вооружения).

## Условия приемки

- GPS1_TYPE и GPS2_TYPE имеют значение 0; EK3_SRC1_POSXY=6;
- наличие обратного подтверждения географического начала отсчета EKF;
- загрузка и обратное чтение маршрутных точек;
- получение не менее 30 высокоточных `SIM_STATE` измерений;
- подтверждение режима AUTO и вооружения в heartbeat;
- **физическое**, по SIM_STATE, удаление виртуального судна от старта больше 15 м;
- посещение каждой из трех маршрутных точек по истинным координатам с минимальным расстоянием менее 4,5 м;
- наличие не менее 20 парных измерений EKF3/физической модели;
- штатный выход C++-передатчика.

Недостаточно одного `MISSION_ACK`, `MISSION_ITEM_REACHED` или `LOCAL_POSITION_NED`: физическая траектория является обязательным внешним относительно EKF критерием.

## Результаты

В `sitl-dynamic-output/` сохраняются:
- `dynamic_mission_report.json` — состояние AUTO, истинная близость к точкам, число пакетов, сообщения ArduPilot и метрики расхождения EKF с физикой;
- `dynamic_sitl_truth.csv` — истинные координаты и оценка EKF;
- `dynamic_cpp_odometry.csv` — данные, направленные C++ в MAVLink;
- `console.log`, `rover.log`, `dynamic_bridge.log` — диагностика.

Если любой требуемый критерий не выполнен, CI должен завершаться с ошибкой. Не публикуйте утверждение «миссия успешно завершена» без конкретного успешного отчета.

Для морской модели следующего этапа требуется, например, поддерживаемая модель BlueBoat/Gazebo с течениями и ветром, затем инерциальная оценка по физически смоделированным IMU и береговым ориентирам вместо прямого использования SIM_STATE.
