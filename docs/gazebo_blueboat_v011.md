# Boat v0.11 — интеграция настоящего BlueBoat/Gazebo (опытная)

## Подтвержденное и неподтвержденное

Этот этап вводит независимый критерий доказательности: **движение физической модели именно BlueBoat должно быть видно в `/model/blueboat/odometry` Gazebo**. Сообщение `SIM_STATE` ArduPilot само по себе недостаточно — оно могло бы поступать из встроенной наземной модели Rover. Тесты ArduPilot и C++-ESKF прежних версий остаются в обычном CI, но **не заменяют** новое испытание Gazebo.

На данный момент готов программный стенд и отдельное задание GitHub Actions, которое должно собрать:
- Gazebo Harmonic;
- `ArduPilot/SITL_Models/Gazebo/models/blueboat` с двумя движителями;
- `srmainwaring/asv_wave_sim` с гидродинамическим и волновыми плагинами;
- `ArduPilot/ardupilot_gazebo` для соединения через JSON SITL;
- ArduPilot Rover с `FRAME_CLASS=2`, двумя выходными каналами `SERVO1_FUNCTION=73` и `SERVO3_FUNCTION=74`, `GPS1_TYPE=GPS2_TYPE=0` и EKF3 ExternalNav;
- C++ ESKF с виртуальными IMU, береговыми дальностями и условным донным лагом.

### Безопасность запуска

Путь `tools/gazebo/run_blueboat_auto.sh` допускает только `--sitl-only` и `route|hold`. Ардуино/контроллеры реального судна не подключаются; JSON и MAVLink ограничены локальной машиной. Прежде чем **изменить миссию или отправить ARM**, клиент должен получить свежий пакет `SIM_STATE` от ArduPilot **и** не менее шести независимых высокоточных физических поз BlueBoat из Gazebo. При отсутствии фактической телеметрии Gazebo испытание завершается отказом, а не переключается на встроенную наземную модель Rover.

Отдельный фоновый наблюдатель сохраняет независимую траекторию `gazebo_blueboat_truth.jsonl`. Истинные данные Gazebo используются для измерения результата и создания **синтетических** датчиков (не реальные IMU/DVL/РЛС), но не подставляются прямо в навигационные координаты, передаваемые ESKF.

### Два обязательных испытания

**Маршрут (`route`):** `AUTO` с тремя точками, активным C++ ESKF и отключенным ГНСС. Приемка требует обратные телеметрические события `MISSION_ITEM_REACHED` 1, 2, 3 и независимое подтверждение движения самой модели BlueBoat по Gazebo (не меньше 5 м). При выполнении теста также сохраняются данные ESKF и ArduPilot.

**Прекращение навигации (`hold`):** после длительной потери береговых ориентиров C++ прекращает недостоверную публикацию ODOMETRY, испытательный наблюдатель командует `HOLD`, ArduPilot обязан подтвердить HOLD через HEARTBEAT. После этого Gazebo продолжает считать физическое движение минимум 20 секунд: фиксируется остаточное смещение корпуса. **Неравенство нулю дрейфа не навязывается** — оно зависит от реальной конфигурации физики Gazebo. Результат `HOLD` не следует интерпретировать как эквивалент удержания координат реальной лодки.

В JSON-результатах разделяются три разные вещи: (1) подтверждение смены режима ArduPilot, (2) истинное движение модели, (3) навигационная ошибка ESKF. При отсутствии любой необходимой части полноценный тест не считается пройденным.

## Запуск

Исходные конфигурации и зависимости (и CI-попытка) находятся в `.github/workflows/blueboat-gazebo.yml`.

Для локального запуска подготовьте `SITL_MODELS_ROOT`, `ASV_WAVE_SIM_ROOT`, `ARDUPILOT_GAZEBO_BUILD` и `ASV_WAVE_SIM_PLUGIN_DIR` с собранными бинарными библиотеками. Проверить:

```bash
bash tools/gazebo/check_blueboat.sh --check-only
```

Далее установить официальный Rover SITL binary и собрать проект с заголовками MAVLink. В **выделенной** программной среде:

```bash
bash tools/gazebo/run_blueboat_auto.sh --sitl-only route
bash tools/gazebo/run_blueboat_auto.sh --sitl-only hold
```

Эти команды действительно запускают Gazebo и виртуальные движители — в отличие от `check_blueboat.sh`.

## Что еще предстоит проверить и реализовать

Это не натурные испытания судна. Даже при успешном Gazebo BlueBoat остается приближенной моделью, а не идентифицированным судном с паспортными коэффициентами. В текущей конфигурации еще не доказано, что **течение и атмосферный ветер** прикладываются как физические силы к BlueBoat в Gazebo: ASV Wave Sim моделирует волновое поле и взаимодействие с корпусом, но параметры волны нельзя автоматически называть заданным водным течением. Приборная модель по-прежнему синтетическая. Корректные сравнительные исследования с течением/ветром нужно создавать отдельными контролируемыми параметрами среды и валидировать изменением физической траектории в Gazebo.

Запись видеоролика на основе v0.10 CSV в чате отражает ранее подтвержденную трехстепенную C++-модель и Rover SITL, **а не** запуск Gazebo. После успешного v0.11 по `gazebo_blueboat_truth.jsonl` и журналам ArduPilot можно генерировать отдельный достоверный видеоматериал испытания BlueBoat.
