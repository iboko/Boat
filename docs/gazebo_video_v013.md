# Boat v0.13 — видео траекторий BlueBoat и проверка потери ГНСС после AUTO

## Что изменилось

В бортовом варианте навигации v0.12 проверялся короткий перерыв приема
ГНСС, но запрограммированный интервал мог закончиться **до вооружения
ArduPilot**. Теперь после фактически подтвержденных `ARMED` и `AUTO`
испытательный наблюдатель подает команду `GNSS_BRIEF_OUTAGE` в C++-модель
датчиков. Через 1 с начинается отказ продолжительностью 3 с.
При исправной ИНС, магнитном курсе и донном лаге ограниченный по времени
режим счисления пути должен сохранять допустимость оценки и позволить
достичь трех маршрутных точек. После восстановления приема ГНСС
коррекция координат возобновляется. Для длительного отказа по-прежнему
требуется прекращение передачи `ODOMETRY` и переход в `HOLD`.

Ни один из этих опытов не подключается к реальному судну. Сигнал отказа
создается только внутри тестовой программы `--sitl-only`.

## Четыре проверяемых видеоматериала

После каждого **успешного** опыта реальной физической модели Gazebo
создается MP4 (H.264) с траекторией по `/model/blueboat/odometry`:

| Сценарий | Имя файла в артефакте CI |
|---|---|
| Береговая коррекция, маршрут AUTO | `route/blueboat_shore_route.mp4` |
| Береговая коррекция, прекращение навигации и HOLD | `hold/blueboat_shore_hold.mp4` |
| Бортовые ГНСС/ИНС/курс/донный лаг, маршрут с кратковременным отказом ГНСС | `onboard-route/blueboat_onboard_route.mp4` |
| Бортовые датчики, длительная потеря ГНСС и HOLD | `onboard-hold/blueboat_onboard_hold.mp4` |

Файлы сохраняются в артефакте `boat-v013-genuine-gazebo-blueboat-with-mp4`
в задании GitHub Actions `BlueBoat Gazebo marine integration (experimental)`.
В архив также входят журналы Gazebo и Rover, результат C++ ESKF,
`dynamic_mission_report.json` и `gazebo_blueboat_verification.json`.

**Существенное отличие:** MP4 представляет собой компьютерную
**визуализацию измеренной модельной траектории**, а не запись с внешней
камеры и не видеозахват окна Gazebo. Координаты X/Y даны в метрах системы
Gazebo. Визуализация явно помечена как ненатурная, показывает подготовку,
движение, подтвержденный HOLD и снос корпуса после него.
Для воспроизводимого просмотра время ускоряется: весь опыт укладывается
в 20 с видео (240 кадров по 12 кадров/с). Нельзя вычислять скорость судна,
время реакции или силы по длительности видео — для этого используются
журналы с исходными временными метками.

## Как получить видео повторно из журналов

При наличии результатов испытаний (`.jsonl` и двух файлов `.json`) можно
создать MP4 без нового запуска Gazebo:

```bash
python3 tools/gazebo/render_blueboat_video.py \
  --truth blueboat-output/onboard-route/gazebo_blueboat_truth.jsonl \
  --mission blueboat-output/onboard-route/dynamic_mission_report.json \
  --verification blueboat-output/onboard-route/gazebo_blueboat_verification.json \
  --output blueboat-output/onboard-route/blueboat_onboard_route.mp4
```

Требуются Python 3, Pillow и FFmpeg с H.264-кодировщиком. Программа
отказывает при отсутствии подтвержденного успешного опыта; данные
`SIM_STATE` или одного только внутреннего фильтра ArduPilot не
принимаются за физическую траекторию BlueBoat.

Для проверки кодировщика без Gazebo:

```bash
python3 tools/gazebo/test_render_blueboat_video.py
```

Этот небольшой тест создает **только синтетические временные примеры**,
проверяет формат MP4 через `ffprobe` и не публикует их как результаты
испытаний BlueBoat.

## Что еще остается

- Повторить новые опыты на нескольких заданных профилях течения и волн;
  параметры водного течения пока не представлены отдельным проверенным
  физическим воздействием в Gazebo.
- Подтвердить сохранение требований к погрешности навигации и задержкам
  при разных характеристиках ИНС, ГНСС, компаса и лага.
- Реализовать контроль препятствий и МППСС-72, независимое управление
  остановкой гребных винтов, а затем перейти к стендовым испытаниям
  аппаратных датчиков.
