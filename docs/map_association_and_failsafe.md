# Boat v0.9 — сопоставление береговых отражений с картой и безопасная остановка

## Архитектура исследовательского контура

Для эксперимента генератор получает истинное положение только из физической модели ArduPilot SITL. Он формирует пять **неподписанных дальностей** до фиксированных обследованных объектов береговой карты и меняет порядок дальностей от кадра к кадру. В этих показаниях нет идентификаторов объектов, готовых координат судна или данных навигационного фильтра.

В модуле `ShoreMapAssociator` каждый отраженный сигнал сравнивается с прогнозом дальности из текущей оценки ИНС/ESKF. Выбирается однозначное соответствие «одно измерение — один береговой объект», ограниченное окном 2,5 м по невязке. Не подходящие под геометрию сигналы отбрасываются; нужно не менее трех сопоставленных ориентиров. Далее `ShoreRangeModel` решает задачу засечки и исключает остаточные выбросы, прежде чем передать геопривязанную коррекцию в ESKF.

Этот метод **зависит от надежного приближенного положения**. Он не решает задачу глобальной релокализации, если начальное положение неизвестно или дрейф превышает допустимое окно поиска. Он также **не** работает с сырым радиолокационным изображением, не оценивает дальность распространения, направление луча, радиолокационную заметность цели, перекрытие береговыми объектами или многолучевость. В одном из численных тестов добавляется заведомо ложное эхо с ошибкой +12 м.

## Контроль целостности оценки при отключенном ГНСС

В штатном моделируемом маршруте короткий пропуск береговых измерений не приводит к остановке. Для исследования продолжительного отказа предусмотрен отдельный сценарий: после 6-й секунды последовательность геопривязанных береговых наблюдений прекращается; когда возраст последнего независимого позиционного измерения превышает 3 секунды, C++ перестает публиковать внешнюю одометрию и создает однозначный диагностический файл `navigation_integrity_failed.txt`. Параметр максимально допустимого возраста определен в `Scenario` и отдельно ограничен.

Испытательный наблюдатель `run_dynamic_mission.py` запускает динамический `AUTO` только после проверки сообщения `SIM_STATE`, которое подтверждает подлинность виртуального симулятора. Увидев маркер аварийной утраты достоверности, наблюдатель отправляет команду смены режима на `HOLD`; **тест засчитывается только после получения HEARTBEAT с подтвержденным режимом HOLD**, а не после отправки команды. Подтверждается также, что судно ранее начало движение и миссия не была успешно завершена до потери навигационной достоверности.

Это **проверка внешнего надзорного клиента в SITL**, а не независимый аппаратный контур безопасной остановки. Сам C++ навигационный модуль пока передает только ODOMETRY и сигнал потери целостности; он не содержит надежного защищенного канала управления реальным рулевым приводом, архитектуры двух независимых вычислителей, сторожевого таймера или расчета безопасной траектории торможения. Режим HOLD не гарантирует удержания физических координат судна при ветре или течении.

## Тестирование

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel
ctest --test-dir build --output-on-failure
```

В CI при наличии ArduPilot Rover SITL выполняются четыре группы сценариев:
- стандартные C++/MAVLink проверки и опыт v0.8;
- штатный маршрут AUTO без ГНСС с анонимными береговыми дальностями и коррекцией ESKF;
- требование отклонить грубые ложные отражатели и подтвердить все три точки в пределах 2,5 м истинного движения по `SIM_STATE`;
- аварийный маршрут с продолжительной потерей береговой коррекции и обязательным подтверждением `HOLD` по телеметрии.

Для каждого опыта сохраняются CSV, журнал надзорного клиента, диагностические сообщения и JSON-отчет. **До успешного CI не следует заявлять, что этап v0.9 проверен.**

## Физическая модель судна — еще не завершена

Текущий SITL использует встроенную физическую модель наземного Rover. Отдельная обучающая модель течения и ветрового сноса `marine_kinematics.cpp` пока не подключена к двигателям ArduPilot. Для полноценной морской модели предусмотрен отдельный контур Gazebo/BlueBoat с плавучестью, сопротивлением, ветром и течением, затем повторное испытание внешней навигации и удержания при потере ориентиров. Нельзя переносить ошибки координат текущего испытания на реальные морские условия.
