# Boat v0.16 — ИНС, достоверность ГНСС, магнитный курс и раздельная тяга

## Назначение

Четыре изменения относятся к исследовательской реализации C++ и ее
виртуальным датчикам. Они не являются подтверждением технических
характеристик серийной ИНС, спутникового приемника или гребных электроприводов.

### 1. Входные измерения ИНС

Трехмерная механизация NED/FRD с 15-состоянийным ESKF сохраняется.
Дополнительно проверяются модули удельной силы и угловой скорости IMU.
Исходные исследовательские границы: 150 м/с² и 12 рад/с.
Недопустимый отсчет не изменяет время и состояние фильтра. Эти значения
нельзя напрямую переносить на датчик без его паспорта и экспериментальной
проверки диапазона, шума, насыщения и частоты измерений.

### 2. Коррекция по ГНСС

Для `AbsoluteSource::Gnss` теперь требуется `GnssQuality` с количеством
использованных спутников (не меньше 6), трехмерным решением, HDOP не выше
4, положительным признаком контроля приемника и отсутствием сообщенной
помехи. Затем выполняется прежняя проверка нормированной инновации по
ковариации ESKF. Невалидное измерение не обновляет `last_gnss_fix_s`.

Отдельный сценарий SITL продолжает выдавать правдоподобные координаты,
но помечает их как ненадежные. Проверяется отказ от коррекции и истечение
разрешенного времени счисления пути без береговых ориентиров.

**Ограничение:** признаки качества приходят от самого приемника. При
необнаруженной имитации/подмене сигналов, согласованном медленном смещении
или ошибке времени эти признаки и проверка единичной невязки не дают
гарантии обнаружения. Требуются независимые проверки и экспериментальная
оценка вероятности опасно пропущенных отказов.

### 3. Магнитный курс

Добавлен отдельный тип `MagneticHeading`: курс продольной оси корпуса
относительно магнитного севера, магнитное склонение, угловая неопределенность,
признаки калибровки и возмущения. Поправка к истинному северу задается
как сумма измеренного магнитного курса и склонения. Угол нормализуется,
поэтому нет разрыва инновации при переходе через +180°/−180°.

Для скалярного наблюдения используется линеаризованная зависимость
курса от правого углового возмущения кватерниона, проверка NIS и
ковариационное обновление в форме Джозефа. При почти вертикальном
направлении продольной оси измерение отклоняется как геометрически
неопределенное. Не вводится фиктивное измерение крена и тангажа.

В тестовом `heading_only_aiding` после первоначальной калибровки
ориентации используется **либо** скалярный магнитный курс, **либо**
старая полная виртуальная ориентация; одновременно они не объединяются,
поскольку получены из одного состояния Gazebo. Режим с одним курсом
не решает самостоятельную задачу коррекции крена/тангажа в условиях качки.

### 4. Динамика корпуса и два гребных винта

В трехстепенной расчетной модели добавлен метод `stepTwinPropulsors`.
Для правой системы FRD/NED:

```
X = T_лев + T_прав
N = l (T_лев − T_прав)
```

где `l` — поперечное плечо винта, `X` — продольная сила,
`N` — положительный по часовой стрелке момент рыскания. Проверяются
пределы тяги каждого винта и согласованность пределов суммарной силы
и момента. По умолчанию `l = 0,28 м`, предельная тяга одного винта
`60 Н`; эти коэффициенты **не идентифицированы** для BlueBoat.

Этот интерфейс не преобразует ШИМ/обороты в силу, не моделирует динамику
электродвигателей, насыщение регуляторов и обратную связь по оборотам.
В существующих Gazebo-сценариях v0.15 физические внешние нагрузки остаются
отдельным экспериментальным модулем.

## Проверка

- `boat_ins_tests`: ограничение IMU, качество ГНСС, неприкосновенность
  состояния при отказе, ковариация и гравитационная механизация.
- `boat_attitude_tests`: магнитное склонение, переход ±π, магнитная
  помеха, NIS, симметрия ковариации и старая коррекция ориентации.
- `boat_onboard_tests`: сценарий помехи ГНСС без исчезновения координат;
  вариант коррекции только по магнитному курсу; отказ по времени счисления.
- `boat_marine_dynamics_tests`: одинаковая тяга двух винтов, моменты
  противоположных знаков, ограничения, течение, ветер и волны.
- Регрессия: старые виртуальные сценарии маршрутов и HOLD без изменения
  их критериев приемки. Полные испытания BlueBoat/Gazebo должны отдельно
  запускаться в GitHub Actions после публикации ветки.

## Остаточные работы

1. Подключить реальные сообщения приемника ГНСС и ИНС с контролем временной
   шкалы, задержек, потери пакетов, установки и юстировки датчиков.
2. Проверить магнитные возмущения от токов гребных электроприводов;
   объединить независимые измерения крена/тангажа без двойного учета.
3. Идентифицировать коэффициенты сопротивления, ветровые нагрузки,
   параметры двух гребных винтов и оценить чувствительность модели.
4. Реализовать независимое аппаратное ограничение тяги и безопасное
   состояние при отказе навигации; затем проводить стендовые испытания.
