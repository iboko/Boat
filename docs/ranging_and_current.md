# Boat v0.8: геометрическая береговая привязка, донный/водный лаг и простая модель ветра и течения

## 1. Что изменилось по сравнению с v0.7

В v0.7 условная береговая «РЛС» сразу выдавала готовые координаты судна. В v0.8 она имитирует **пять измеренных дальностей** до известных береговых ориентиров в фиксированной системе координат NED. В тесте положение известно лишь физическому источнику, формирующему дальности. Алгоритм береговой привязки получает только ID ориентира и дальность, а **не истинное положение**.

Геометрическая оценка строится по трем непараллельным наблюдениям, затем сравнивается с оставшимися и уточняется по многократным измерениям невязки дальности. Искусственный выброс +12 м в дальности к одному ориентиру позволяет проверить отбраковку неверного наблюдения. Для решения нужны минимум три корректных измерения; вырожденная геометрия, повторные ID и некорректные дальности отвергаются.

**Ограничения:** ориентиры здесь заранее идентифицированы и имеют известные координаты. Нет радиолокационных изображений, сканирования, выделения целей, геометрической ассоциации, затенений, многолучевого распространения и оценки видимости. Это **задача многопозиционной засечки по дальностям**, а не завершенная навигация по радиолокационной карте.

## 2. Два режима доплеровского лага

В режиме донного отслеживания выдаваемая лагом скорость относится к земной системе; ее можно использовать для коррекции скорости ESKF. Если донное отслеживание потеряно, модель переводит лаг в режим относительно воды:

\[
\mathbf v_{\rm water}=\mathbf v_{\rm ground}-\mathbf v_{\rm current}+\varepsilon.
\]

В испытательной модели задано условное течение `v_N=0,35` м/с, `v_E=-0,20` м/с. Скорость относительно воды **не подается** в коррекцию земной скорости ESKF без отдельной оценки течения. В журнале записываются переключения режимов и количество отвергнутых водно-относительных измерений.

**Важно:** течение изменяет моделируемое показание водного лага, **но пока не влияет на физическое движение** в основном испытании ArduPilot Rover SITL.

## 3. Упрощенная двумерная модель движения

Отдельный модуль `include/boat/marine_kinematics.hpp` и `src/marine_kinematics.cpp` описывает движение на горизонтальной плоскости с раздельными скоростями относительно воды и грунта, первым порядком изменения водной скорости и условным боковым воздействием ветра. Проверка `boat_marine_tests` сравнивает неподвижную среду с течением и ветром.

Модуль используется **как самостоятельная кинематическая модель для проверки единиц измерения и допущений**. Это не шестистепенная гидродинамическая модель корпуса, не симуляция волнения и пока **не** динамика двигателей и рулевого устройства ArduPilot. Указывать такие тесты как «натурную морскую навигацию» нельзя.

## 4. Автоматические проверки

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel
ctest --test-dir build --output-on-failure
```

В обязательные проверки входят:
- согласованность решения по дальностям для нескольких положений;
- устойчивость к добавленному выбросу дальности +12 м;
- отказ при отсутствии наблюдаемости и повторных номерах ориентиров;
- запрет подмены скорости относительно воды скоростью относительно дна;
- тест упрощенного течения и ветрового сноса;
- регрессия существующего ESKF.

При доступности официального ArduPilot Rover SITL в GitHub Actions дополнительно проверяются отключение ГНСС, `AUTO`, достижение каждой точки по эталонной физической траектории, вывод ESKF, количество береговых дальномерных засечек, наличие отбраковки выброса и переключение в режим водного отслеживания.

## 5. Что осталось

Для физически обоснованного морского решения требуются модель распространения РЛ-сигнала, ассоциация и сопровождение береговых отражателей, акустическая лучевая модель донного лага, оценивание течения, определение абсолютного курса и полноценная гидродинамика корпуса с ветром, течением и волнением. Далее — подключение реальных датчиков и стендовая/натурная валидация.
