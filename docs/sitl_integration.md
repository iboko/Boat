# ArduPilot SITL: проверка внешней навигации Boat (эксперимент)

## Что реализовано в Boat v0.3

- **C++ TCP MAVLink 2**: подключение только к `127.0.0.1` через порт SERIАL1 SITL (обычно 5762), проверка heartbeat именно ArduPilot, передача кадров `ODOMETRY`.
- **Проверка данных перед отправкой**: необходимо достоверное состояние 3D ИНС, известные и согласованные NED-координаты, измерение высоты, калиброванная ориентация, свежие независимые координаты при запрете использования ГНСС. Ошибки и устаревшие измерения блокируют передачу.
- **Экспериментальная статическая модель** `boat_sitl_bridge --sitl-fixture`: создает *синтетическую* неподвижную лодку с инерциальными и «береговыми» измерениями и отправляет `ODOMETRY` с частотой 10 Гц. Эти измерения не поступают с настоящей РЛС.
- **Автотест настоящего исполняемого Rover SITL**: загрузка официального предсобранного `ardurover`, запуск с `FRAME_CLASS=2`, `GPS1_TYPE=0`, `GPS2_TYPE=0`, `EK3_SRC1_POSXY=6`, TCP-соединение и 80 сообщений `ODOMETRY`.
- **Самостоятельный протокольный тест**: имитатор MAVLink-сервера проверяет handshake и полноценное декодирование переданной одометрии.

## Строгое разграничение результатов

Успешная передача и TCP-обмен с Rover **не означают**, что его EKF3 принял эти измерения, оценил координаты и выполнил маршрут. Для такого утверждения нужны сообщения статуса EKF3, сообщения состояния и лог DataFlash, проверка `SET_GPS_GLOBAL_ORIGIN` при отсутствии ГНСС, загрузка/выполнение миссии и независимая метрика отклонения от пути.

Из-за отсутствия реальных датчиков и радиолокационной привязки нельзя заявлять, что лодка уже плавает без ГНСС.

## Сборка

Нужны CMake 3.20+, компилятор C++20, POSIX, заголовки MAVLink C v2:

```bash
cmake -S . -B build-mavlink -DBOAT_WITH_MAVLINK=ON \
  -DBOAT_MAVLINK_INCLUDE_DIR=/path/to/mavlink/c_library_v2
cmake --build build-mavlink --parallel
ctest --test-dir build-mavlink --output-on-failure
```

## SITL

В CI запускается `bash tools/sitl/run_sitl_smoke.sh`, который использует официальный предсобранный исполняемый Rover по пути из переменной `ARDUROVER_BINARY`, либо `sitl-smoke-output/ardurover`.

Во внешнем терминале можно самостоятельно запустить штатный `sim_vehicle.py -v Rover -f boat --no-mavproxy` из клона ArduPilot, затем подключить `./build-mavlink/boat_sitl_bridge --sitl-fixture --port 5762 --seconds 12`.

При использовании настоящего SITL с отключенным ГНСС необходимо отдельно установить EKF origin через `SET_GPS_GLOBAL_ORIGIN` и проверить его подтверждение. Не изменяйте предпусковые проверки или параметры контроллера для реальной лодки по копии параметров SITL.

## Следующий приоритет

1. Добавить инъекцию симулированных IMU, РЛС и донного лага, согласованную с **физической моделью Rover**, чтобы внешняя одометрия следовала настоящему виртуальному движению (а не была постоянной точкой).
2. Проверить подтверждение `EK3_SRC1_POSXY=6` и корректность `SET_GPS_GLOBAL_ORIGIN` в настоящий Rover.
3. Запрограммировать миссию из нескольких маршрутных точек и подтвердить по DataFlash/модельной траектории факт движения именно от ExternalNav без ГНСС.
4. Добавить испытания при исчезновении береговых ориентиров и превышении ошибки координат: переход в безопасный режим.
